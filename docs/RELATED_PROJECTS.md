# Related open-source projects

Reviewed 2026-10-14 against the upstream GitHub repository pages and READMEs. Project scope and capabilities may change; consult each upstream project for current details. Camera Exploration Lab is intended to complement these tools through reproducible Linux camera experiments, trustworthy performance analysis, education, and eventual simultaneous multi-camera measurement. It does not claim to be the first or only project in these areas. No third-party source code was copied for this review.

| Project | Verified focus | Overlap and complementary value | Interoperability or learning opportunity |
| --- | --- | --- | --- |
| [v4l-utils](https://github.com/gjasny/v4l-utils) | Linux media utilities and libraries, including `v4l2-ctl`, `qv4l2`, `qvidcap`, topology and compliance tools. | It provides lower-level device inspection and control; the Lab records camera identity, host timing, settings evidence, and repeatable sessions. | Link to V4L2 capability and format inspection; use its tools as an independent check of driver readback. |
| [cameractrls](https://github.com/soyersoyer/cameractrls) | Python command line and GTK interfaces for V4L2 and additional camera controls, presets, PTZ, and control restoration. | It focuses on interactive controls; the Lab currently focuses on experiments and separates requested from reported settings. | Learn from its control discovery and readback UX; consider launching or documenting compatible control utilities without duplicating their implementation. |
| [Webcamoid](https://github.com/webcamoid/webcamoid) | Cross-platform webcam capture and management, effects, streaming and recording, virtual cameras, and desktop capture. | It is a general webcam application; the Lab emphasizes research provenance and measurement method. | Use virtual camera workflows for synthetic integration checks and compare capture configuration behavior. |
| [FLIR-Multicam](https://github.com/nicthib/FLIR-Multicam) | Python multi-camera acquisition built around FLIR Spinnaker / PySpin, including hardware-trigger or free-run operation and multithreaded saving as described upstream. | It addresses multi-camera acquisition for a specific FLIR SDK and camera family; CEL-013 targets per-camera V4L2 measurements and does not assume hardware synchronization. | Study its per-camera acquisition and save boundaries; keep the Lab backend-neutral and label hardware trigger support only when proven. |
| [uvc-astrotools](https://github.com/graphworlok/uvc-astrotools) | UVC/V4L2 camera characterization such as exposure fidelity, noise, shading, hot pixels, and auto-exposure, alongside astronomy observation and image-analysis tools. | It offers specialized image-quality and astronomy analysis; the Lab targets reusable throughput/timing experiments across ordinary Linux cameras. | Learn from repeatable test patterns and exposure characterization; future optional extensions could consume saved measurements without adding astronomy dependencies to core. |
| [latencytool](https://github.com/mstoeckl/latencytool) | Measures a visual app-screen-camera-app flicker path using camera capture, OpenCV/V4L backends, and multiple frontends. | Its stimulus-to-observation loop targets end-to-end latency. The Lab's ordinary frame intervals and OpenCV read durations do not measure sensor latency. | Document a possible external optical test protocol and distinguish its event boundaries and uncertainty from host capture throughput. |
| [calibcam](https://github.com/bbo-lab/calibcam) | Charuco-based multi-camera intrinsic and extrinsic calibration, including mixed lens types and synchronized or constant-offset video inputs, with reprojection-error plots. | It focuses on geometry and calibration; CEL-013 is a future measurement workflow and does not provide calibration or synchronization guarantees. | Consider documented handoff of captured frame sets and calibration metadata to specialized tools; keep calibration dependencies in an optional extension. |

## Project boundary

The core Lab should stay small: camera discovery, V4L2 capture, experiment recording, history, and analysis. Specialized controls, astronomy tests, latency protocols, calibration, and computer vision can be linked or implemented behind optional adapters when there is a concrete need. Read-only V4L2 inspection and CSV/JSON measurement exchange are practical integration points. CEL-013 Multi-Camera Workbench remains the next major functional milestone, with separate host-arrival timelines and an explicit statement that those timestamps do not establish sensor synchronization.
